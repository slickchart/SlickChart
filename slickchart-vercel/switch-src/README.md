# Switching guides (`/switch`)

Generated by `node scripts/build-switch.cjs` (run from `slickchart-vercel/`). Same chrome, SEO head
and markdown subset as the blog — see `scripts/lib/site-chrome.cjs` and `scripts/lib/md.cjs`.

- `index.md` → `/switch` — the hub. Always published; it describes SlickChart, not someone else's product.
- `from-<platform>.md` → `/switch/from-<platform>` — one per platform.

## The publish gate

A `from-<platform>.md` page only goes live when **both** are true:

1. **The file exists and is hand-written for that platform.** Never generate these by swapping a name
   into a template. Fifteen near-identical pages differing only by a brand name is what Google calls
   scaled content abuse, and it would put the whole domain at risk. If you cannot say something
   specific and true about that platform, there should be no page for it.
2. **`import-profiles.json` has `verified: true` for that platform id** — somebody has actually
   followed that export path inside the live product.

`scripts/lib/switch-guides.cjs` enforces this, and `build-switch.cjs` prints what is being held back
and why. `build-blog.cjs` reads the same gate when writing `sitemap.xml`, so a page can never be
listed in the sitemap without existing, or exist without being listed.

## Verifying a platform (about three minutes)

You need access to a real account on that platform — a free trial is fine. Then:

1. Log in and find the client/customer list export. Write down the **exact** menu path you clicked.
2. Export a CSV, even with two rows in it.
3. Open the file and write down the **exact header names** in row one.
4. Put the path into `steps` and the headers into `aliases` in `import-profiles.json`, and set
   `verified: true`, `lastVerified: <YYYY-MM-DD>`, and `verifiedBy: <who did it and how>`.
5. Write `switch-src/from-<id>.md` with something specific to that platform. Then rebuild.

Do not set `verified: true` from documentation, a support article, a web search, or memory. The flag
means one thing: a person followed those clicks and got a file.

## House rules for the copy

- **Never state a competitor's pricing, plan names or feature list from memory.** Same rule as the
  blog (`blog-src/README.md`). Describe what *SlickChart* does; let the reader compare.
- Say what does not come over (photos, appointment history, payments) before the reader has to find
  out. A guide that only lists wins is an ad.
- The Square referral disclosure is appended by the generator to every page. Don't hand-write one.
- Frontmatter rules are the blog's: `title` must stay under 60 characters once ` | SlickChart` is on,
  and `description` between 70 and 160 characters. The build fails loudly otherwise.
